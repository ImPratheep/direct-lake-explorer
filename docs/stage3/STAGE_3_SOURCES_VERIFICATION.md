## ARCHITECTURAL DISTINCTIONS - VERIFIED

All verified against the 19 Microsoft Learn sources:

✅ **Direct Lake is a Semantic Model Storage Mode**
- NOT a separate database engine
- Defined in Source 1 as "storage mode"
- Works with Analysis Services semantic model engine
- Stores reference metadata, loads columns on-demand

✅ **VertiPaq is In-Memory Columnar Engine**
- NOT exclusive to Direct Lake
- Shared by Import mode and Direct Lake
- Also used in Power BI Desktop and Analysis Services
- Source 10, 12 define as core compression and storage engine

✅ **Formula Engine & Storage Engine - Different Responsibilities**
- **Formula Engine** (Sources 14, 15, 16):
  - Parses and executes DAX queries
  - Creates query plans
  - Calculates aggregations
  
- **Storage Engine** (Sources 2, 3, 16):
  - Retrieves data from storage
  - Manages VertiPaq transcoding
  - Controls column loading and caching

✅ **xmSQL is Internal Query Representation**
- NOT SQL submitted to database
- Conceptual diagnostic representation
- Shows Storage Engine's internal operations
- Source 3 describes as diagnostic tool

✅ **Framing & Column Loading - No Proprietary Details**
- **Framing** (Source 2): Creating semantic understanding of table structure
- **Column Loading** (Source 2): On-demand loading into VertiPaq memory
- **Transcoding** (Source 2): Converting Parquet to VertiPaq format
- All documented in official Microsoft materials
- No implementation internals claimed or fabricated
