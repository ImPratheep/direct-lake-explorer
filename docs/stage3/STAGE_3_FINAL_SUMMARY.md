#### ✅ Direct Lake is a Semantic Model Storage Mode
- **Representation:** Shown as storage mode in Layer 2 Semantic
- **NOT claimed as:** Separate database engine
- **Accuracy:** Correctly positioned with Import and DirectQuery
- **Sources:** RESEARCH_SOURCES #1-4
- **Verification:** ✅ ACCURATE

#### ✅ VertiPaq is In-Memory Columnar Engine
- **Representation:** Dedicated Layer 3 with encoding/compression
- **NOT claimed as:** Exclusive to Direct Lake
- **Accuracy:** Correctly shown as shared (Import + Direct Lake)
- **Sources:** RESEARCH_SOURCES #10, #12
- **Verification:** ✅ ACCURATE

#### ✅ Formula Engine and Storage Engine Different Responsibilities
- **Formula Engine:**
  - Receives DAX queries
  - Parses syntax
  - Creates query plans
  - Calculates results
  - Returns final data
  - **Shown in:** Layer 4 Query Phase 2
  - **Sources:** RESEARCH_SOURCES #14-16
  - **Verification:** ✅ ACCURATE

- **Storage Engine:**
  - Retrieves from OneLake
  - Transcodes Parquet → VertiPaq
  - Loads columns on-demand
  - Manages cache/eviction
  - Optimizes via segment elimination
  - **Shown in:** Layer 4 Query Phases 3-5
  - **Sources:** RESEARCH_SOURCES #2-3, #16
  - **Verification:** ✅ ACCURATE

#### ✅ xmSQL is Internal Query Representation
- **Representation:** Shown in Layer 4 Query Phase 4
- **Classification:** Marked [SIMULATION]
- **NOT claimed as:** SQL sent to relational database
- **Accuracy:** Diagnostic representation of SE operations
- **Sources:** STAGE_2_RESEARCH_SUMMARY.md §11
- **Verification:** ✅ ACCURATE

#### ✅ Framing and Column Loading Accuracy
- **Framing:**
  - Metadata-only operation
  - No data loaded yet
  - Lightweight snapshot creation
  - **Shown in:** Layer 2 Semantic
  
- **Column Loading:**
  - On-demand transcoding
  - Parquet → VertiPaq format
  - Triggered by query
  - **Shown in:** Layer 3 VertiPaq
  
- **No proprietary details:** All from Microsoft Learn
- **Sources:** RESEARCH_SOURCES #2
