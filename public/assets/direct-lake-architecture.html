Architecture Overview

This five-layer isometric cutaway illustrates the complete Microsoft Fabric Direct Lake data pipeline, from persistent OneLake storage through semantic framing, VertiPaq encoding, query processing, and memory management. The illustration traces the path of a DAX query as it moves through each layer, showing how data flows from cold storage through increasingly optimized representations to fast in-memory cache.

Five Architectural Layers

1. Storage Layer

OneLake foundation with Delta Lake transaction logs, Parquet files organized into row groups, and column chunks with statistics.

  • OneLake Container
  • Delta Table + _delta_log
  • 8 Parquet Files
  • Row Groups (128 MB each)
  • Column Chunks
  • Statistics (min/max)
✓ DOCUMENTED

2. Semantic Layer

Direct Lake framing creates table snapshots and metadata, enabling lightweight metadata-only refreshes without data reload.

  • Framing Metadata
  • Table Snapshot
  • Column Definitions
  • Column Selection
  • Partition Info
  • Refresh Marker
✓ DOCUMENTED

3. VertiPaq Layer

In-memory columnar encoding layer using dictionary/hash encoding, segment organization, and compression to maximize data density.

  • Dictionary Encoder
  • Hash Encoder
  • 8 Segments (~8K rows)
  • Segment Statistics
  • Encoding Selection
  • Compression Engine
[SIMULATION]

4. Query Layer

DAX query execution through Formula Engine (planning) and Storage Engine (retrieval), with six sequential query phases.

  • DAX Query Entry
  • Formula Engine
  • Storage Engine
  • xmSQL Representation
  • 6 Query Phases
  • Segment Elimination
[SIMULATION]

5. Memory Layer (Subject)

Column cache management showing residency, memory pressure thresholds, and LRU eviction policies under capacity constraints.

  • Column Cache
  • 4 Loaded Columns
  • Residency Tracking
  • Memory Pressure Gauge
  • LRU Eviction Policy
  • Reloading Mechanism
[SIMULATION]

Data Flow Path

Query Execution Pipeline (6 Phases):

  1. Query Submission (user interaction)
  2. Formula Engine (DAX parsing & planning)
  3. Column Loading (identify required columns)
  4. Segment Elimination (apply predicates)
  5. Transcoding & Aggregation (assembly)
  6. Results Return (delivery to user)
